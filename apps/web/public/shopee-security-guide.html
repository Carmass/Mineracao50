1. Visão Geral

A Shopee Open Platform protege os dados empresariais dos vendedores e os dados pessoais dos usuários considerados sensíveis — incluindo nome do cliente, número de telefone, endereço de e-mail e endereço.

Por padrão, os dados sensíveis são mascarados. Para ter acesso aos dados sem máscara, os desenvolvedores precisam cumprir requisitos específicos de segurança.

ℹ️
Este documento descreve os dois requisitos obrigatórios para solicitar acesso a dados sensíveis: o Relatório de Teste de Penetração (para ISVs que atendem vendedores na Tailândia) e o IP Whitelist (obrigatório para todos os desenvolvedores).

2. Requisitos de Elegibilidade

Para solicitar acesso a dados sensíveis de negócios, os desenvolvedores devem atender às seguintes condições:

01
Relatório de Teste de Penetração
ISV — Tailândia apenas

Exigido para desenvolvedores de Plataformas Parceiras de Terceiros (ISV) que atendem ou planejam atender vendedores na Tailândia.

Um relatório de teste de penetração válido deve ser enviado através do Console da Open Platform.

02
IP Address Whitelist
Todos os desenvolvedores

Os endereços IP dos servidores que hospedam sua aplicação devem ser declarados e incluídos na whitelist.

Obrigatório para todos os desenvolvedores, independente da região ou tipo de conta.

2
anos de validade do acesso Para desenvolvedores ISV aprovados, o acesso a dados sensíveis é válido por dois (2) anos a partir da data de emissão do relatório de teste de penetração.
⚠️
Atenção (ISVs): O acesso aprovado a dados sensíveis é válido por dois (2) anos a partir da data de emissão do relatório de teste de penetração. Após esse período, é necessário submeter um novo relatório para renovar o acesso.

3. Como Enviar o Relatório de Teste de Penetração

Siga os passos abaixo para fazer o upload do relatório:

  1. Acesse o Console da Open Platform com sua conta de desenvolvedor.
    Contas de membro não têm permissão para fazer upload de relatórios.
  2. Navegue até Central Pessoal → Informações da Conta
    ISVs da China Continental: acesse pelo link específico para CN.
    ISVs de outras regiões: acesse pelo link de outras regiões.
  3. Em Informações de Relatórios e Certificações de Segurança, clique em "Adicionar".
  4. Em Tipo de Relatório e Certificação de Segurança, selecione "Relatório de Teste de Penetração".
  5. Faça upload do seu relatório de teste de penetração mais recente.
    Formatos aceitos: PDF, JPG, JPEG, PNG (máx. 10 MB).
    Para relatórios com mais de uma página, envie em formato PDF.
    A certificação de segurança pode ser ISO 27001, SOC 2, PCI DSS ou outra equivalente.
  6. Clique em "Salvar" para concluir o envio.
📌
O status do envio (Aprovado / Rejeitado) será atualizado na seção Informações da Conta. Consulte a seção de Boas Práticas ao final deste documento antes de preparar seu relatório.

4. Prazo de Análise

Após o envio, o resultado da análise ficará disponível dentro do prazo indicado abaixo:

10
dias úteis O resultado da análise (Aprovado / Rejeitado) é geralmente disponibilizado em até 10 dias úteis. O status será atualizado na seção Informações da Conta do Console.

5. Como Habilitar o IP Address Whitelist

Para habilitar o IP whitelist na sua aplicação:

  1. Faça login no Console da Open Platform e acesse Lista de Apps.
  2. Selecione o app que requer acesso a dados sensíveis.
  3. Clique em "Go Live" e preencha as informações solicitadas.
  4. Em "IP Address Whitelist", insira o(s) endereço(s) IP do(s) servidor(es) que hospedam sua aplicação.
  5. Ative o botão "Enable IP Address Whitelist" para ON.
  6. Clique em "Submit" para salvar as configurações.
⚠️
Importante: Uma vez que o IP Whitelist esteja habilitado, as chamadas de API só poderão ser feitas a partir de aplicações hospedadas no(s) endereço(s) IP declarado(s). Qualquer IP não listado será bloqueado.

6. Boas Práticas para Envio do Relatório de Pentest

6.1 Provedores de Teste Recomendados

Para melhorar a qualidade do relatório e a eficiência da análise, os ISVs são incentivados a contratar testadores de penetração credenciados e respeitáveis.

✅
Para todos os ISVs: Utilize testadores de penetração credenciados pelo CREST.

Para ISVs com sede na China (CN): Recomendamos testadores credenciados por:

奇安信 — Qianxin
Empresa de segurança cibernética, China
360 Security
Empresa de segurança digital, China
深信服 — Sangfor
Segurança de redes e nuvem, China
长亭科技 — Chaitin
Segurança cibernética, China
ℹ️
Relatórios de outros testadores de penetração ainda serão analisados e considerados para aprovação caso a caso.

6.2 Requisitos de Qualidade do Relatório

Um Relatório de Teste de Penetração completo deve:

  • Refletir a exposição externa da aplicação (superfície de ataque acessível pela internet)
  • Avaliar vulnerabilidades em todos os sistemas ou aplicações relevantes
  • Incluir uma lista completa de descobertas (findings), incluindo vulnerabilidades de todos os níveis de severidade
  • Confirmar que nenhum problema crítico ou de alto risco permanece sem solução

6.3 Data de Emissão Recomendada

1
ano — janela recomendada de emissão Os ISVs são incentivados a enviar um relatório de teste de penetração emitido dentro do último um (1) ano.

O acesso a dados sensíveis será concedido por dois (2) anos a partir da data de emissão do relatório.

7. Checklist de Conformidade

Use este checklist antes de submeter sua solicitação de acesso a dados sensíveis:

  • Conta de desenvolvedor (não de membro) ativa no Console da Open Platform
  • Relatório de teste de penetração emitido há menos de 1 ano (ISVs — Tailândia)
  • Relatório emitido por testador credenciado pelo CREST ou equivalente aprovado
  • Relatório em formato PDF (se possuir mais de uma página), máximo 10 MB
  • Nenhuma vulnerabilidade crítica ou alta sem resolução documentada no relatório
  • Endereços IP do(s) servidor(es) da aplicação identificados e disponíveis
  • IP Whitelist habilitado (ON) no painel do app no Console
  • Prazo de revisão considerado: até 10 dias úteis após envio
  • Renovação agendada antes da expiração dos 2 anos de validade
